# 診断要約アーキテクチャ

## 設計思想
VIS の AI 要約は「言語化ファースト」を原則とする。

### 原則 1: 数値説明の禁止
- スコアやギャップを直接説明させない
- スコアを「状態」に翻訳した上で AI に渡す

### 原則 2: 構造情報の活用
- insight_spec から抽出した テーマ・難易度・ファネル を最優先
- これらの「組み合わせ」「分布」「バランス」を診断の軸とする

### 原則 3: 根拠の後付け
- 結論・意味を先に述べ、数字は根拠として最後に
- プロンプト上で「数字は最後に」と明示

## Config ベースの拡張

`diagnostic_config.yaml` で以下を一元管理：
- **診断閾値**: スコアを「高・中・低」に分類する基準
- **ラベル翻訳**: theme / funnel / difficulty を日本語に翻訳
- **将来の新ラベル追加**: Python 修正なしで YAML 追加のみで対応

## テスト方針

### ユニットテスト（10 件）
- 診断関数の出力に「数字が含まれないこと」を強制
- Config の翻訳テーブルが正しく機能するかを検証
- エッジケース（低スコア、欠損ラベル等）に対応

### 後戻り防止テスト
- 「数値説明への後戻り」を検出する専用テスト
- CI/CD で常時チェック（将来 GitHub Actions 導入時）

## 今後の拡張

### Phase 4（将来）
- `diagnostic_config.yaml` に新ラベルを追加
- テストは既存テストのみで対応可能

### 新ラベル追加の手順
1. `diagnostic_config.yaml` に翻訳テーブルを追記
2. `diagnostic_summary.py` の関数は修正不要
3. テストは既存テストで自動カバー
