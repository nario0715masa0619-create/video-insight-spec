# FREE TRIAL ONE VIDEO OPERATION
無料1本解析（VIS体験デモ）運用ガイド

## 1. 目的
本ドキュメントは、商談時に依頼された「無料1本解析」を、担当者が迷わず実行・返却できるようにするための運用手順をまとめたものです。

本フローは、自動ダウンロードや複雑な受付機能を使わず、担当者が手動で動画ファイルを所定フォルダへ配置し、VISに通して結果を返却する最小構成を前提とします。

---

## 2. 対象範囲
本運用で対応するもの:
- 顧客から受領した動画ファイル1本の解析
- ダッシュボードでの品質診断・改善提案の実演
- 顧客返却用レポート（report.md）の出力（※補助資料として後送）

本運用で対応しないもの:
- YouTubeからの自動ダウンロード
- 複数動画の一括解析
- 外部フォーム連携
- 大規模な案件管理
- 自動メール送信
- 新分析軸の追加

---

## 3. 前提環境
### 3.1 利用環境
- 本番環境: `D:\AI_スクリプト成果物\video-insight-spec`
- 開発環境: `D:\AI_スクリプト成果物\video-insight-spec-dev`

### 3.2 現在の基準版
- 安定運用版: `v1.5.x` 系

### 3.3 基本方針
- 無料1本解析は、既存VISの価値をダッシュボード上で実演（デモ）するための運用とする
- 標準提供内容 = 「ダッシュボード実演」 + 「必要に応じて report.md を後送」
- 出力は「数値説明」ではなく「品質診断」「改善提案」を中心とする
- 実務で迷わず回せることを優先する

## 4. フォルダ構成
無料1本解析では、以下の構成を使用する。

- `incoming/`
  - 顧客から受領した元動画を置く
- `processing/`
  - 解析中の動画を一時的に置く
- `completed/`
  - 処理済みの元動画を移動する
- `deliverables/`
  - 顧客返却用成果物を出力する
- `logs/`
  - 実行ログを保存する
- `cases/`
  - 案件メタデータ（`cases.yaml`）を管理する

※ 実際のルートパスは、運用設定に従うこと。

---

## 5. 命名規則
案件は以下の形式で命名する。

- `trial_会社名_YYYYMMDD`

例:
- `trial_abccompany_20260609`

### 5.1 ファイル命名例
- 元動画:
  - `trial_abccompany_20260609_source.mp4`
- 返却レポート:
  - `trial_abccompany_20260609_report.md`

命名規則は、案件・元動画・返却物が追跡できることを目的とする。

## 6. 必要情報
無料1本解析の登録時には、最低限以下を用意する。

必須:
- `case_id`
- `client_name`
- `video_file`

任意:
- `focus`（見てほしい観点）
- `memo`（担当者メモ）
- `expected_delivery`（返却期限）

## 7. 運用フロー
### Step 1. 動画受領
営業または担当者が顧客から動画ファイルを受領する。

確認事項:
- 動画ファイル形式
- 動画タイトル
- クライアント名
- 見てほしい観点（あれば）
- 希望返却日（あれば）

---

### Step 2. 案件登録
`cases.yaml` に案件情報を登録する。

登録例:
```yaml
- case_id: trial_abccompany_20260609
  client_name: ABC Company
  video_file: trial_abccompany_20260609_source.mp4
  focus: "この動画の強み・弱みと、次に作るべき動画の方向性を見たい"
  memo: "営業商談用の無料診断"
  expected_delivery: "2026-06-12"
```

### Step 3. 動画配置
受領した動画を `incoming/` に配置する。

注意:
- ファイル名は案件IDと対応するようにする
- 既存案件と重複しないか確認する

### Step 4. 実行
無料1本解析用スクリプトを実行する。

実行例（プロジェクトのルートディレクトリから実行）:
```bash
python scripts/run_free_trial_one_video.py --case-id trial_abccompany_20260609
```
※ Windowsで文字化けやエラーが出る場合は `$env:PYTHONIOENCODING="utf-8"` を実行してから実行してください。
Windows補助バッチを使う場合:
```bash
run_free_trial.bat trial_abccompany_20260609
```

### Step 5. 処理内容
実行時、以下が行われる。
1. 入力チェック
2. `incoming/` から対象動画を取得
3. 必要に応じて `processing/` へ移動またはコピー
4. 既存VIS分析フローで1本解析
5. 診断結果を `deliverables/` へ出力（※report.mdは補助資料）
6. 実行ログを `logs/` に保存
7. 完了後、元動画を `completed/` へ整理

### Step 6. 実演準備（営業確認用）
商談前に、ダッシュボードが正しく表示されるか確認する。

営業が確認しやすい簡易チェックリスト:
- ✅ ダッシュボード起動確認
- ✅ 対象動画が正しく読み込まれているか
- ✅ 品質診断が表示されているか
- ✅ 改善提案が表示されているか
- ✅ 営業が説明できる状態か

### Step 7. 商談時の実演（ダッシュボード）
商談では、ダッシュボード画面を共有しながら説明する。

商談時の標準見せ方:
1. 最初に「品質診断」タブで診断結果（役割・強み・弱みなど）を見せる
2. 次に「改善提案」タブで具体的アクション（最優先・次点）を見せる
3. 必要に応じて他のタブ（黄金の組み合わせ、隠れた弱点など）を補足で見せる

返却時に強調するポイント:
- 今どういう状態か
- 何が強みか
- 何が不足しているか
- 次に何を優先すべきか

### Step 8. 後送資料の送付
商談後、必要に応じて `report.md` を顧客に送付する。
※ `report.md` はあくまで実演の補助資料という位置づけ。

## 8. 返却物の基本構成
無料1本解析の返却物には、最低限以下を含める。

### 8.1 対象動画
- 動画タイトル
- クライアント名
- 案件ID

### 8.2 品質診断
- 現在の役割
- 構造上の強み
- 構造上の弱み
- 欠けている橋渡し

### 8.3 改善提案
- 最優先アクション
- 次点のアクション
- 対応順
- 期待される効果

### 8.4 一言まとめ
- 商談でそのまま使える短い要約

## 9. 失敗時の確認先
実行が失敗した場合は、以下を確認する。

- `cases.yaml`
  - `case_id` が正しいか
  - `video_file_name` が一致しているか
- `incoming/`
  - 対象動画が存在するか
  - ファイル名が正しいか
- `logs/`
  - エラー内容
  - 実行時ログ
  - 中断箇所
- 実行環境
  - 必要な環境変数
  - Python実行環境
  - 既存VISの起動条件

## 10. 運用ルール
### 10.1 無料枠の基本ルール
- 対象は1動画のみ
- 最小構成で返却する
- 返却物は「品質診断」「改善提案」を中心にする
- 過剰な個別カスタマイズは行わない

### 10.2 返却品質
- 数値説明中心に戻さない
- 状態診断型の日本語を維持する
- 商談でそのまま使える読みやすさを保つ

### 10.3 例外対応
以下は原則として本フロー外とする。
- 動画が複数本ある
- 顧客が比較分析を求める
- 個別の特別フォーマット納品を求める
- 追加深掘り分析を求める

必要に応じて別案件化する。

## 13. FAQ / トラブルシューティング

### Q1. `ModuleNotFoundError: No module named 'config'` などの Import エラーが出る
**A1.** 実行時のカレントディレクトリが間違っているか、不要な Import が残っている可能性があります。
- 必ずプロジェクトの**ルートディレクトリ**（`video-insight-spec-dev` または `video-insight-spec`）でターミナルを開き、`python scripts/run_free_trial_one_video.py` を実行してください。
- `scripts/` ディレクトリの中に `cd` してから実行するとエラーになります。

### Q2. 実行時に `UnicodeEncodeError: 'cp932' codec can't encode character...` が出る
**A2.** Windows のデフォルトエンコーディングによるエラーです。
PowerShell で実行する前に以下のコマンドを入力して文字コードを UTF-8 に設定してください。
```powershell
$env:PYTHONIOENCODING="utf-8"
```
