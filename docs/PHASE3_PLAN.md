# Phase 3 計画案（backlog）

## 概要
Phase 2 で確立したユニットテスト基盤を活かし、
システム全体のビジネスフロー（エンドツーエンド）での
正確性と自動化を実現するフェーズ。

## タスク 1: 統合テスト（E2E）基盤構築

### 目的
ダッシュボール起動 → データロード → 表示 までの一連フロー検証
バッチ実行 → JSON生成 → ダッシュボード反映 までの流れ検証

### 対象範囲
- ダッシュボール全体のフロー
- バッチからダッシュボード反映までの流れ
- 大量データ時のパフォーマンス

### 期間目安
1 週間

## タスク 2: CI/CD パイプライン案の立案・PoC

### 目的
PR 作成時に自動テスト実行
main へのマージ時に品質チェック自動化

### 対象プラットフォーム
GitHub Actions

### 内容
- Python Lint（flake8, mypy）
- pytest 自動実行
- カバレッジレポート生成（オプション）

### 期間目安
1 週間

## タスク 3: ドキュメント統合

### 目的
テスト実行方法、CI/CD 運用ガイド、セットアップガイドを README に統合

### 対象ドキュメント
- README.md
- docs/TESTING.md（新規）
- docs/CI_CD_GUIDE.md（新規）

### 期間目安
3 日

## 優先度
全タスク中優先度は「中」
他の機能追加タスクがあれば、それを優先してもよい

## 開始判断基準
- Phase 2 の安定性が確認された場合
- チーム内で品質基盤整備の優先度が上がった場合
